C.3 流水线是怎样实现的

讨论基本流水线之前，先回顾 RISC-V 非流水线版本的一种简单实现。

RISC-V 的简单实现

本节沿用 C.1 节的写法，先给出一种简单的非流水线实现，再给出流水线实现。不同的是，这一次的例子专门针对 RISC-V 体系结构。

这一小节讨论 RISC-V 一个整数子集的流水线，这个子集包括 load/store 字、相等转移和整数 ALU 操作，基本的浮点操作在本附录后面加入。虽然只讨论一个子集，但基本原理可以推广到全部指令。例如，加入 store 指令时，需要对立即数字段做一些额外的计算。转移指令先采用一种不那么激进的实现，本节最后再说明怎样实现更激进的版本。

每条 RISC-V 指令最多用 5 个时钟周期就能实现，这 5 个时钟周期如下。

  1. 取指周期（IF）：

    IR ← Mem[PC];
NPC ← PC + 4;

    操作：送出 PC，从存储器取出指令，放进指令寄存器（IR）；PC 加 4，指向顺序的下一条指令。IR 保存后续时钟周期要用到的指令；同样，寄存器 NPC 保存顺序的下一个 PC。

  2. 译码/读寄存器周期（ID）：

    A ← Regs[rs1];
B ← Regs[rs2];
Imm ← sign-extended immediate field of IR;   // IR 中立即数字段的符号扩展

    操作：对指令译码，访问寄存器堆读出寄存器（rs1 和 rs2 是寄存器号）。两个通用寄存器的输出读入临时寄存器 A 和 B，供后面的时钟周期使用。同时，IR 的低 12 位做符号扩展后存入临时寄存器 Imm，供下一个周期使用。

    译码与读寄存器可以并行进行，因为这些字段在 RISC-V 指令格式中的位置是固定的。load 指令和 ALU 立即数指令的立即数部分在每条 RISC-V 指令中都位于相同的位置，所以这个周期也算出符号扩展后的立即数，以备下一个周期使用。store 指令的立即数字段分成两段，需要另做一次符号扩展。

  3. 执行/有效地址周期（EX）：

    ALU 对上一周期准备好的操作数做运算，按 RISC-V 指令的类型完成以下四种功能之一。

    • 访存指令：

      ALUOutput ← A + Imm;

      操作：ALU 把两个操作数相加，形成有效地址，结果放进寄存器 ALUOutput。

    • 寄存器-寄存器 ALU 指令：

      ALUOutput ← A func B;

      操作：ALU 对寄存器 A 和寄存器 B 中的值执行功能码（func3 字段和 func7 字段的组合）指定的运算，结果放进临时寄存器 ALUOutput。

    • 寄存器-立即数 ALU 指令：

      ALUOutput ← A op Imm;

      操作：ALU 对寄存器 A 和寄存器 Imm 中的值执行操作码指定的运算，结果放进临时寄存器 ALUOutput。

    • 转移指令：

      ALUOutput ← NPC + (Imm << 2);
Cond ← (A == B)

      操作：Imm 中是符号扩展后的立即数，左移 2 位成为字偏移量，ALU 把它与 NPC 相加，算出转移目标地址。由于只考虑相等转移，判断转移是否成功的方法是比较上一周期读出的寄存器 A 和寄存器 B。

    RISC-V 是 load-store 体系结构，没有哪条指令需要同时计算数据地址、计算指令目标地址并对数据做运算，因此有效地址周期和执行周期可以合并成一个时钟周期。这里没有列出的其他整数指令是各种形式的跳转，与转移指令类似。

  4. 访存/转移完成周期（MEM）：

    所有指令都更新 PC：PC ← NPC;

    • 访存指令：

      LMD ← Mem[ALUOutput] or
Mem[ALUOutput] ← B;

      操作：需要时访问存储器。load 指令从存储器取回数据，放进 LMD（load memory data，取存储器数据）寄存器；store 指令把 B 寄存器中的数据写入存储器。两种情况所用的地址，都是上一周期算出、存放在寄存器 ALUOutput 中的地址。

    • 转移指令：

      if (cond) PC ← ALUOutput

      操作：如果转移成功，就用寄存器 ALUOutput 中的转移目标地址替换 PC。

  5. 写回周期（WB）：

    • 寄存器-寄存器或寄存器-立即数 ALU 指令：

      Regs[rd] ← ALUOutput;

    • load 指令：

      Regs[rd] ← LMD;

    操作：把结果写入 rd 指定的寄存器。结果可能来自存储系统（在 LMD 中），也可能来自 ALU（在 ALUOutput 中）。

图 C.18 画出了一条指令怎样流过数据通路。每个时钟周期结束时，凡是本周期算出、后面的时钟周期还要用到的值（无论是本条指令用还是下一条指令用），都写进某个存储部件。存储部件可能是存储器、通用寄存器、PC，也可能是临时寄存器（即 LMD、Imm、A、B、IR、NPC、ALUOutput 或 Cond）。临时寄存器在同一条指令的各个时钟周期之间保存值；其他存储部件属于可见状态，在相继的指令之间保存值。

图 C.18　按这种方式实现 RISC-V 数据通路，每条指令都能在 4 个或 5 个时钟周期内执行完。图中 PC 画在取指用的那部分数据通路中，寄存器画在译码/读寄存器用的那部分数据通路中，但指令对这两个功能部件既要读，也要写。图中按读这两个部件的周期来安排它们的位置，实际上 PC 在访存周期写入，寄存器在写回周期写入。这两处后面流水段的写操作，都用（访存段或写回段的）多路选择器输出表示，多路选择器把一个值送回 PC 或寄存器。这些反向流动的信号意味着可能出现冒险，流水线的复杂性大部分由此而来。图内标注：Instruction fetch，取指；Instruction decode/register fetch，译码/读寄存器；Execute/address calculation，执行/地址计算；Memory access，访存；Write-back，写回；Add，加法器；Instruction memory，指令存储器；Registers，寄存器堆；Sign-extend，符号扩展；Mux，多路选择器；Branch taken，转移成功；Data memory，数据存储器；ALU output，ALU 输出。

如今所有处理器都采用流水线，但早年大多数处理器的实现方式与这种多周期实现相当接近。控制部分可以按这里给出的五周期结构，用一个简单的有限状态机实现；复杂得多的处理器可以采用微码控制。无论哪种方式，控制的结构都由本节所述的这种指令序列决定。

这个多周期实现中有些硬件是冗余的，可以去掉。例如，数据通路中有两个 ALU：一个用来递增 PC，另一个用来计算有效地址和完成 ALU 运算。两者不会在同一个时钟周期用到，因此可以增加几个多路选择器，把它们合并成一个 ALU。同样，数据访问和指令访问发生在不同的时钟周期，所以指令和数据也可以放在同一个存储器中。

我们不去优化这个简单的实现，图 C.18 的设计保持不变，因为它更适合作为流水线实现的基础。

RISC-V 的基本流水线

和前面一样，只要每个时钟周期启动一条新指令，图 C.18 的数据通路几乎不用改动就能流水化。每个流水段在每个时钟周期都在工作，因此一个流水段中的所有操作必须在 1 个时钟周期内完成，而且各种操作无论怎样组合，都必须能够同时进行。此外，流水化之后，从一个流水段传给下一个流水段的值必须放在寄存器中。图 C.19 画出了 RISC-V 流水线，每两个流水段之间都加了一组寄存器，称为流水线寄存器或流水线锁存器，名字取自它们连接的两个流水段。从图 C.19 可以清楚地看出，各段之间是怎样经由流水线寄存器相连的。

一条指令在时钟周期之间需要暂存的值，现在全部放进这些流水线寄存器。指令寄存器（IR）属于 IF/ID 寄存器，IR 中提供寄存器名的字段在图中都标了出来。流水线寄存器把数据和控制信息从一个流水段带到下一个流水段。后面的流水段要用的值，都必须放进流水线寄存器，并逐级复制下去，直到不再需要为止。如果只沿用前面非流水线数据通路中的临时寄存器，一个值可能还没用完就被覆盖了。例如，load 或 ALU 操作写寄存器时，目的寄存器字段取自 MEM/WB 流水线寄存器，而不是 IF/ID 寄存器。因为我们要让 load 或 ALU 操作写它自己指定的寄存器，而不是此刻正从 IF 进入 ID 的那条指令所指定的寄存器！这个目的寄存器字段只是逐级复制，到 WB 段才用到。

图 C.19　在每两个相邻流水段之间加上一组寄存器，数据通路就流水化了。这些寄存器把值和控制信息从一个段传到下一个段。PC 也可以看作一个流水线寄存器，位于流水线的 IF 段之前，这样每个流水段都对应一个流水线寄存器。前面说过，PC 是边沿触发的寄存器，在时钟周期结束时写入，因此写 PC 不存在竞争条件。PC 的选择多路选择器移了位置，使 PC 只在一个段（IF）中写入。如果不移，发生转移时两条指令会向 PC 写入不同的值，从而产生冲突。数据通路大多从左向右流动，也就是从时间上较早的段流向较晚的段。从右向左流动的通路（携带寄存器写回信息和转移时的 PC 信息）使流水线变得复杂。图中标注：Instruction memory 为指令存储器，Registers 为寄存器堆，Sign-extend 为符号扩展，Data memory 为数据存储器，ADD 为加法器，Mux 为多路选择器，=? 为相等比较，Branch taken 为转移成功；IR19..15、IR24..20 为 IR 中的两个源寄存器字段，12、32 为符号扩展前后的位数。

任一时刻，一条指令恰好处于流水线的一个段中，因此为这条指令所做的操作都发生在一对流水线寄存器之间。于是，我们也可以换个角度看流水线的活动：按指令类型，看每个流水段必须完成哪些操作。图 C.20 就是从这个角度画的，流水线寄存器各字段的名字反映了数据从一段流向下一段的过程。可以看出，前两个流水段的操作与当前指令的类型无关。它们也必须无关，因为指令要到 ID 段结束时才完成译码。IF 段的操作取决于 EX/MEM 中的指令是不是成功的转移：如果是，就在 IF 结束时把 EX/MEM 中这条转移指令的目标地址写入 PC；否则写回递增后的 PC。（前面说过，转移的这种影响会使流水线变得复杂，接下来几节就处理这个问题。）寄存器源操作数采用固定位置编码，这一点至关重要，正是靠它才能在 ID 段读取寄存器。

图 C.20　RISC-V 流水线各流水段的操作。下面回顾一下各段中与流水线组成有关的操作。在 IF 段，除了取指令、计算新的 PC，还把递增后的 PC 同时存入 PC 和一个流水线寄存器（NPC），供以后计算转移目标地址时使用。这与图 C.19 的组成相同：在那里，PC 在 IF 段从两个来源中选一个来更新。在 ID 段，读取寄存器，对 IR 中的 12 位（立即数字段）做符号扩展，并把 IR 和 NPC 传下去。在 EX 段，执行 ALU 操作或地址计算，并把 IR 和 B 寄存器（如果是 store 指令）传下去；如果指令是成功的转移，还把 cond 置为 1。在 MEM 段，完成一次存储器访问，必要时写 PC，并把最后一个流水段需要的值传下去。最后，在 WB 段，用 ALU 的输出或 load 取回的值更新寄存器字段所指定的寄存器。为简单起见，我们总是把整个 IR 从一段传到下一段，尽管指令沿流水线前进时，用到的 IR 部分越来越少。图中标注：Stage 为流水段，Any instruction 为任意指令，ALU instruction 为 ALU 指令，Load instruction 为 load 指令，Branch instruction 为转移指令，or 为「或者」，For load only 为「仅对 load 指令」。

要控制这条简单的流水线，只需确定图 C.19 数据通路中四个多路选择器怎样设置：

  • ALU 段的两个多路选择器按指令类型设置，指令类型由 ID/EX 寄存器的 IR 字段决定。ALU 上输入端的多路选择器看指令是不是转移，下输入端的多路选择器看指令是寄存器-寄存器 ALU 操作还是其他类型的操作；
  • IF 段的多路选择器决定把递增后的 PC 还是 EX/MEM.ALUOutput（转移目标）写入 PC，由 EX/MEM.cond 字段控制；
  • 第四个多路选择器看 WB 段中的指令是 load 还是 ALU 操作。

除了这四个，还需要一个多路选择器。它没有画在图 C.19 中，但看一下 ALU 操作的 WB 段就知道它必不可少：目的寄存器字段的位置随指令类型而不同，寄存器-寄存器 ALU 操作在一处，ALU 立即数操作和 load 在另一处。因此，如果指令要写寄存器，就需要一个多路选择器从 MEM/WB 寄存器的 IR 中选出正确的部分，作为目的寄存器字段。

RISC-V 流水线控制的实现

在这条流水线中，指令从译码段（ID）进入执行段（EX）的过程通常称为指令发射（instruction issue），完成了这一步的指令称为已发射的指令。RISC-V 整数流水线的所有数据冒险都可以在 ID 段检查：如果存在数据冒险，指令在发射之前就停顿下来。同样，需要哪些前递也可以在 ID 段确定，并在这时设置好相应的控制。在流水线的早期检测互锁，可以降低硬件复杂度，因为这样一来，除非整个处理器停顿，硬件永远不必挂起一条已经更新了处理器状态的指令。另一种做法是在使用操作数的那个时钟周期（这条流水线中是 EX 和 MEM）开始时检测冒险或前递。为了说明两种做法的区别，下面举两个例子：一是在 ID 段做检查，实现源操作数来自 load 指令的写后读（RAW）冒险的互锁，这种互锁称为 load 互锁；二是在 EX 段实现通往 ALU 输入端的前递通路。图 C.21 列出了必须处理的各种情况。

流水线中转移的处理

RISC-V 的条件转移要比较两个寄存器的值，我们假设比较在 EX 周期由 ALU 完成。此外还要计算转移目标地址。转移开销有多大，取决于转移条件的测试和下一个 PC 的确定在何时完成，因此我们希望在 EX 周期结束之前算出两个可能的 PC，并选出正确的那个。办法是增加一个单独的加法器，在 ID 段计算转移目标地址。这时指令还没有译码，所以只能把每条指令都当作转移指令，算出一个可能的目标地址。这样做很可能比在 EX 段既算目标地址又求转移条件要快，但能耗确实略高一些。

这条流水线的转移开销为两个周期。一些早期的 RISC 处理器（如 MIPS）限制了转移的条件测试，使测试能在 ID 段进行，从而把转移延迟缩短为一个周期。当然，这样一来，一条 ALU 操作写某个寄存器，紧接着一条条件转移依据这个寄存器做判断，就会产生数据冒险；在 EX 段求转移条件则没有这种冒险。

流水线加深，转移延迟随之增大，于是动态转移预测成为必需。例如，如果处理器把译码和读寄存器分成两个段，转移延迟很可能至少多出 1 个时钟周期。转移延迟不加处理，就会变成转移开销。许多实现较复杂指令系统的老处理器，转移延迟达到 4 个时钟周期甚至更多；大型深流水线处理器的转移开销常常是 6 或 7 个周期。激进的高端超标量处理器，如第 3 章讨论的 Intel i7，转移开销可能达到 10～15 个周期！一般来说，流水线越深，以时钟周期计的转移开销就越大，准确预测转移也就越关键。
