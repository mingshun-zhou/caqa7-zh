## 疑似原书错误（译文照原文）

- 第 32 页 i7 6700 一句：“more than one reference made to a block with an outstanding miss (1.23 references on average with a range from 0.5 to 3.0)”。说「超过一次」，范围下限却是 0.5，前后矛盾。照原文译。
- 第 36 页图 2.15 图注说 “the 15 most intensive memory benchmarks”，图中横轴实际有 17 个程序（perlbench … xz）。照原文译「15 个」。
- 第 36 页图 2.15 图注 MKPI3 与正文 MPKI3 拼法不一，纵轴标注又写作 MKI3；均按 MPKI3 理解，图注统一写 MPKI3。
- 第 36 页正文「two benchmarks that more than double performance」：图中 CPI 比低于 0.5 的有 lbm（约 0.45）和 fotonik3d（约 0.35），与「两个」一致；「five that get an improvement of about 10% or less」与图大体相符。照原文。
- 第 35 页正文 L2 预取器的名称：原文 DCUI 为 “L1 Data cache unit prefetcher”、DCUP 为 “instruction pointer stride prefetcher”。Intel 文档通常是 DCU（下一行）预取器和 DCU IP 预取器，原书缩写与全称的对应可能颠倒。照原文译。
- 第 40 页 “very large blocks can generate a higher miss rate, especially for conflict and consistency misses”：一般说法是 conflict / coherence（或 capacity）失效，“consistency misses” 用词少见。照原文译「一致性失效」。
- 第 41 页图 2.16 图注 “SPECCPI2006” 应为 SPECCPU2006，译文写 SPECCPU2006；纵轴 “Spedup” 为原图拼写错误，图未改。
- 第 41 页 “good misprediction results”：意思应是预测效果好（误预测少），译「预测结果又好」。
- 第 42 页图 2.17：「指令和数据的硬件预取」一行的说明是 “Most provide prefetch instructions; modern high-end processors also automatically prefetch in hardware”，「编译器控制的预取」一行的说明末尾是 “in many CPUs”。前者的内容更像编译器预取的说明，两行说明疑似错位。照原表逐行译。
- 第 42 页图 2.17 HBM 一行：带宽列为 +/–，失效开销列为 –，失效率和功耗列为 +。照页面图录入。
- 第 43 页正文说 “Generally, no technique helps more than one category”，而图 2.17 中多数行有两个以上的 +。照原文译。
- 第 38 页例题说 “We underline the changes to the preceding code”，但 PDF 页面图中的代码看不到下划线，Markdown 代码块也无法加下划线。译文保留这句话，代码照录。可考虑改用 HTML 代码块加 `<u>`，或删掉这句之外另想办法，请统稿时定。

## 本节新定术语

- critical word first 关键字优先；early restart 提前重启（首次注英文）。
- loop interchange 循环交换；blocking 分块；blocking factor 分块因子；blocked algorithm 分块算法；row / column major order 行优先顺序 / 列优先顺序。
- stream buffer 流缓冲器；instruction stream buffer 指令流缓冲器。
- register prefetch / cache prefetch 寄存器预取 / Cache 预取。
- faulting / nonfaulting prefetch 引发异常的 / 不引发异常的预取（首次注英文）；nonbinding prefetch 非绑定预取；“semantically invisible” 语义上不可见的；no-op 空操作。
- hardware prefetching 硬件预取；compiler-controlled prefetching 编译器控制的预取。
- DCUI、DCUP、L2A、L2P 保留缩写；L1 数据 Cache 单元预取器、指令指针步长预取器、L2 数据 Cache 空间预取器、L2 数据 Cache 流预取器。
- MPKI（Misses Per K Instructions）每千条指令失效数（MPKI）；MPKI3 指 L3 的 MPKI。
- software pipelining 软件流水（附录 H）。
- memory channel 存储通道；memory bus 存储总线；HBM stack HBM 堆叠；signaling convention 信号约定。
- NUMA 非一致存储结构（NUMA）（原文全称 NonUniform Memory Architecture，与常见的 Non-Uniform Memory Access 不同，按原文译「结构」）。
- L-H scheme L-H 方案；Loh-Hill scheme Loh-Hill 方案；alloy cache 合金 Cache（首次注英文）；SRAM tags SRAM 标签方案；miss predictor 失效预测器；Ideal 理想情况（Ideal）。
- burst transfer 突发传输（与 02-memory-02 一致）；CAS latency CAS 延迟；column access 列访问。
- LLC 直接用缩写（应在 2.1 节定义为「最后一级 Cache」）。
- 图 2.17 表头：Hit time 命中时间、Bandwidth 带宽、Miss penalty 失效开销、Miss rate 失效率、Power consumption 功耗、Hardware cost/complexity 硬件成本/复杂度、Comment 说明。行名：Small and simple caches 小而简单的 Cache；Way-predicting caches 路预测 Cache；Pipelined & banked caches 流水化 Cache 和多体 Cache；Merging write buffer 合并写缓冲；HBM as additional level of cache HBM 作为附加的一级 Cache。需与 2.3 节第一部分（第一至第五种优化）的小标题统一。
- 小标题格式：十种优化用 `### 第 N 种优化：…… {-}`；循环交换、分块是原书斜体小标题，用 `####`（第 1 章 01-fundamentals-09 有先例）。
